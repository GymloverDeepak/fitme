# FITME

An offline bodybuilding companion for Android, built with React Native, Expo SDK 58 and plain JavaScript.
No backend, no database server, no login, no paid APIs.

Designed & developed by **Gymlover Deepak**.

## Features

- **Home dashboard** — greeting, daily motivation, today's workout from your chosen plan, Start Workout, water tracker, session stats, quick links, daily tips.
- **Workout planner** — 7 sample plans: Beginner 3/4-day, Intermediate 4/6-day and Advanced Push/Pull/Legs (6), Upper/Lower (4) and Bro Split (5). Weekly schedule with rest/recovery days.
- **Exercise library** — 72 exercises (Beginner, Intermediate, Advanced) across Chest, Back, Shoulders, Biceps, Triceps, Legs & Glutes, Core & Abs and Compound & Variations. Search by name; filter by difficulty, muscle group and equipment. Each exercise has secondary muscles, equipment, sets/reps/rest, form steps, safety notes and a spotter indication.
- **Exercise demonstrations** — every exercise has an original animated stick-figure demonstration (start → end with direction arrow, real play/pause, start/end stills) plus thumbnails on exercise cards. Drawn in code: offline, no image files, no licences.
- **Custom workouts** — add/remove/reorder exercises and edit sets, reps, rest and warm-up sets per day. Built-in plans are never overwritten; "Reset to default" restores them.
- **Workout sessions** — start/resume/finish/discard, tick off individual working sets (warm-ups shown separately), completion counts, rest timer (start, pause, reset), session summary.
- **Deadlift Training Planner** — conventional, sumo, Romanian and trap-bar. Conservative strength estimate (lower of Epley/Brzycki, never a max test), working-weight suggestions rounded to your bar and plates, warm-up generator, manual override of everything, kg/lb display, schedule and recovery warnings, pre-lift safety checklist, set checklist with RPE logging, notes, stop-early reasons, previous-session summary, next-session recommendation (never auto-increases), reduced-volume option, PRs and strength trend.
- **Indian diet planner** — Muscle gain / Fat loss / General fitness × Vegetarian / Non-vegetarian, 4 meals a day with serving sizes, calorie and protein estimates, hydration and nutrition guidance.
- **Progress** — workout history, water history, body weight and optional measurements, saved on the phone.
- **Settings** — kg/lb and cm/in units, water goal, theme info, clear all data, About screen.

## Project structure

```
App.js                     App entry: safe area, error boundary, data loading, splash, navigation
index.js                   Registers App (generated by Expo, unchanged)
app.json                   Expo config: name, Android package, icon, splash
eas.json                   EAS cloud build profiles (preview = APK)
assets/
  images/gymlover-deepak-logo.png   Original logo (source for all icons)
  icon.png, android-icon-*.png, splash-icon.png, favicon.png   Generated from the logo
scripts/
  generate-assets.ps1      Rebuilds icon/splash images from the logo
  check.mjs                Data-integrity and logic checks (npm run check)
src/
  components/              Reusable UI (buttons, cards, timer, footer, logo…)
  data/                    Static content: workouts.js, dietPlans.js, tips.js, appInfo.js
  hooks/useCountdown.js    Rest-timer logic
  navigation/              AppNavigator.js (tabs + stack), routes.js (screen names)
  screens/                 One file per screen
  storage/                 AsyncStorage wrapper, data validation, app state provider
  theme/                   Colours, spacing, typography
  utils/                   Dates, units, input validation
```

## Setup (Windows)

Requires Node.js 20+ and npm.

```powershell
cd D:\FitMe
npm install
```

## Develop and test with Expo Go

1. Install **Expo Go** from the Play Store (SDK 58 compatible).
2. Put the phone and PC on the same Wi-Fi.
3. Run `npm start` and scan the QR code with Expo Go.
   If the network blocks it, use `npx expo start --tunnel`.

Always add packages with `npx expo install <package>` (not `npm install`) so versions match SDK 58.

## Quality checks

```powershell
npm run lint     # ESLint (Expo config)
npm run check    # data integrity + validation/storage/date logic
npm run doctor   # Expo dependency and config health
npx expo export --platform android   # compiles the full Android JS bundle
```

## Building the APK

### Production release (signed with the FITME release key) — use this for distribution

```powershell
cd D:\FitMe
powershell -ExecutionPolicy Bypass -File scripts\build-release.ps1
```

The script runs lint, the logic checks and expo-doctor, regenerates `android/`, restores the Windows build
settings, builds with the private release key and **refuses to finish if the APK is debug-signed**.
Output: `release\FITME-v<version>.apk` (git-ignored) plus its size, SHA-256, version and signer.

Release signing setup (already done on the development PC):

| Item | Location | In git? |
| --- | --- | --- |
| Keystore | `%USERPROFILE%\.fitme-signing\fitme-release.jks` (alias `fitme`) | **Never** |
| Password | `%USERPROFILE%\.fitme-signing\fitme-release-password.txt` (or typed when the script asks) | **Never** |
| Path + alias | `%USERPROFILE%\.gradle\gradle.properties` (`FITME_UPLOAD_STORE_FILE`, `FITME_UPLOAD_KEY_ALIAS`) | No |
| Gradle wiring | `plugins/withReleaseSigning.js` (reads the values above; contains no secrets) | Yes |

**Back up the keystore and its password** (for example a USB drive plus a password manager). If either is
lost, you can never publish an update that installs over existing copies of FITME.

Before each new release, raise `version` and `android.versionCode` in `app.json`.

### Option A — local test build (debug-signed, not for distribution)

Needs JDK 17 and the Android SDK (both installed on the development PC).

```powershell
cd D:\FitMe
npx expo prebuild --platform android --clean
cd android
.\gradlew.bat assembleRelease
```

The APK is written to `android\app\build\outputs\apk\release\app-release.apk`.

**Windows one-time setup** (React Native's C++ build creates paths longer than 260 characters):

1. Enable long paths once, in an *Administrator* PowerShell:
   `New-ItemProperty -Path "HKLM:\SYSTEM\CurrentControlSet\Control\FileSystem" -Name "LongPathsEnabled" -Value 1 -PropertyType DWORD -Force`
2. Install a CMake whose ninja supports long paths:
   `& "$env:ANDROID_HOME\cmdline-tools\latest\bin\sdkmanager.bat" --install "cmake/3.31.6"`
3. After every `prebuild --clean`, recreate `android\local.properties` with:
   ```
   sdk.dir=C\:/Users/<you>/AppData/Local/Android/Sdk
   cmake.dir=C\:/Users/<you>/AppData/Local/Android/Sdk/cmake/3.31.6
   ```

To build faster for real phones only (skips emulator CPU types):
`.\gradlew.bat assembleRelease "-PreactNativeArchitectures=arm64-v8a,armeabi-v7a"`

Notes:
- `prebuild` regenerates the `android/` folder from `app.json`. Never edit `android/` by hand; it is git-ignored.
- `prebuild` changes the `android` and `ios` scripts in `package.json` to `expo run:*`. Change them back to `expo start --android` / `expo start --ios` if you want `npm run android` to keep using Expo Go.
- This build is signed with the debug key, which is fine for installing on your own phones but **not** for the Play Store.

Install on a USB-connected phone (USB debugging on):

```powershell
& "$env:ANDROID_HOME\platform-tools\adb.exe" install -r android\app\build\outputs\apk\release\app-release.apk
```

### Option B — EAS cloud build (free tier, needs an Expo account)

```powershell
npm install -g eas-cli      # or use npx eas-cli@latest
eas login                   # your Expo account
eas init                    # links the project (adds a projectId to app.json)
eas build --platform android --profile preview
```

The `preview` profile in `eas.json` produces an installable **APK**. When the build finishes, EAS prints a build page URL; open it (or https://expo.dev → your project → Builds) and use **Download** / **Install** to get the APK. Free accounts may wait in a queue.

Docs: https://docs.expo.dev/build/setup/ · https://docs.expo.dev/build-reference/apk/

### Installing the APK on a phone

1. Copy the APK to the phone (USB, Google Drive, etc.) or open the EAS download link on the phone.
2. Tap the file. Android will ask you to allow installs from that source (e.g. *Files* or *Chrome*) — allow it once.
3. If an older FITME build signed with a different key is installed, uninstall it first.

### Releasing an update

1. Make changes and run the quality checks.
2. In `app.json`, increase `version` (e.g. `1.0.1`) **and** `android.versionCode` (e.g. `2`). Android refuses to install an update with the same or lower versionCode.
3. Rebuild with Option A or B.

## Troubleshooting

| Problem | Fix |
| --- | --- |
| Expo Go says the project is incompatible | Update Expo Go from the Play Store. |
| `npx expo-doctor` reports version mismatches | `npx expo install --fix` |
| Gradle: `JAVA_HOME is not set` / wrong Java | Set `JAVA_HOME` to a JDK 17 folder. |
| Gradle: SDK location not found | Set `ANDROID_HOME` to your Android SDK folder. |
| Gradle: licences not accepted | `& "$env:ANDROID_HOME\cmdline-tools\latest\bin\sdkmanager.bat" --licenses` |
| `ninja: error: mkdir(...): No such file or directory` | Windows path-length limit — do the one-time setup above (long paths + CMake 3.31.6 + `cmake.dir`), delete `android\app\.cxx`, rebuild. |
| Strange build errors after changing `app.json` | `npx expo prebuild --platform android --clean`, then build again. |
| "App not installed" on the phone | Uninstall the old FITME first (different signing key), or check free storage. |
| `npm audit` shows vulnerabilities | They come from Expo's dev tooling. Do **not** run `npm audit fix --force` — it breaks SDK compatibility. |

## Data and privacy

All data (settings, water log, sessions, body weight, measurements) is stored only on the phone with AsyncStorage under versioned `fitme:v1:*` keys. It is not synced or backed up. Settings → *Clear all data* deletes it. No name, email or other personal profile data is stored.

## Known limitations

- Single device only: no sync, backup or export.
- Nutrition values are rounded estimates for plain ingredients; recipes, brands and oil change real values.
- Workout and diet plans are general samples, not personalised or medical advice.
- One dark theme; it does not follow the system light/dark setting.
- The rest timer runs only while its screen is open (by design) and does not send notifications.
- Exercise demonstrations are simplified 2D stick figures (side, front or top view). Rotations such as the Arnold press twist and some movements across the body are described in the cue text rather than shown.
- Deadlift strength estimates are approximate. All loads are suggestions and must be adjusted to readiness and technique.
- Local release APKs are debug-signed. For the Play Store, build an AAB with `eas build --profile production` (EAS manages a proper upload key).
